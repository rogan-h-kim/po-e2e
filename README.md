# 🍰 Po-Cake

배포된 사이트를 **코드 수정 없이** 테스트하는 노코드 E2E 레코더 크롬 익스텐션.
토스 발표의 _Cake_ 컨셉을 참고해, **접근성(role/name) 기반 셀렉터 + CDP 신뢰 이벤트 재생**으로 정확도를 우선한 구현입니다.

## 설계 요약

| 레이어                 | 역할                                                              | 정확도 포인트                                    |
| ---------------------- | ----------------------------------------------------------------- | ------------------------------------------------ |
| **Side Panel (React)** | 녹화/재생/스텝 관리 UI                                            | -                                                |
| **Content Script**     | 요소 선택·하이라이트, 접근성 셀렉터 생성, 녹화(엿듣기), 위치 탐색 | ① 요소 선택 정확도 (role/name 우선, 유일성 검증) |
| **Background + CDP**   | `chrome.debugger`로 **신뢰(trusted) 마우스/키 이벤트** 재생       | ② 동작 재현 정확도                               |

셀렉터 우선순위: `testid` → `role+name` → `text` → `css`(경고).
동일 요소가 여러 개면 `nth`로 특정하고 경고를 표시합니다. (Cake의 "홈페이지 바로가기 2개" 케이스 대응)

## 개발 / 빌드

```bash
npm install
npm run build      # tsc 타입체크 + eslint + vite 빌드 → dist/
npm run dev        # HMR 개발 모드 (crxjs)
npm run lint       # eslint 만 실행
```

## 크롬에 설치 (Load unpacked)

1. `npm run build` 실행 → `dist/` 생성
2. 크롬에서 `chrome://extensions` 열기
3. 우측 상단 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드합니다** → `dist/` 폴더 선택
5. 툴바의 Po-Cake 아이콘 클릭 → **사이드 패널** 열림

## 화면 구성

사이드 패널은 실행자에게 두 탭(**시나리오 · 설정**), 게시자에게 세 탭(**시나리오 · 게시 · 설정**)입니다. 시나리오를 누르면 시나리오 탭 안에서 상세 화면으로 들어가고 `←`로 돌아옵니다. 상단에는 항상 **버전** 선택과 게시 버전, `↻`가 있습니다.

| 탭           | 무엇을 하나                                                                                                                                                                                                                                                                                                                                          |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **시나리오** | 버전의 시나리오를 **폴더별**로 보고 실행. 시나리오 하나 ▶, 폴더 ▶, 전체 ▶, 또는 **체크박스로 골라 선택 재생**(폴더 헤더 체크로 폴더 전체 선택). 각 시나리오에 최근 결과. 아래에 내 초안. 시나리오를 누르면 **상세 화면**: 재생 목록(번호 · 설명 · 결과 · ⋯ 메뉴), 행 사이 "여기에 단계 추가", 하단 바(단계추가 · 녹화하기 · 전체 재생 · 게시), 실행 기록, 재생 설정. 실행자의 팀 시나리오는 읽기 전용(복제해서 편집) |
| **게시** | 버전 전체를 폴더 트리로 보여주고 시나리오마다 상태(게시됨 · 변경됨 · 새 항목 · 삭제됨) 표시. 변경된 것만 체크해 **선택 게시**하거나 **모두 게시**, 되돌리기. 아래에 제품 버전 관리 |
| **설정**     | 게시자 로그인, 재생 옵션, JSON 내보내기/불러오기                                                                                                                                                                                                                                                                                                     |

**폴더**는 버전 안의 한 단계 분류예요 (기능 영역: `AI Draft`, `AI Meeting Notes`, `home`, `tray` …). 게시자가 시나리오 탭에서 `＋ 폴더`로 만들고, 편집 탭의 폴더 드롭다운으로 시나리오를 옮깁니다. 폴더는 버전과 함께 게시되고, 버전을 복사하면 폴더도 같이 복사됩니다.

## 사용법

- **＋ 단계추가**: "무엇을?"에서 종류(클릭·입력·옵션 선택·키·페이지 이동·대기·검증 5종)를 고르고, 요소가 필요하면 **화면에서 선택** → 페이지에서 요소를 클릭하면 폼에 채워짐
- **● 녹화 시작**: 실제로 클릭·입력·드롭다운 선택·Enter/Esc/Tab 키를 누르면 단계가 자동으로 쌓임.
  빈 시나리오에서 시작하면 현재 페이지 URL이 첫 단계(**페이지 이동**)로 자동 추가되어, 누가 어디서 재생하든 같은 페이지에서 시작합니다
- **＋ 페이지 이동 / ＋ 키 입력 / ＋ 대기 / ＋ URL 검증**: URL 이동, 단일 키 입력(Enter·Escape·Tab·Backspace·화살표), 대기(ms), 현재 URL 검증 단계를 직접 추가
- **검증 종류**: 보임 · 텍스트 나타남(아무 글자) · 텍스트 포함/일치 · 입력값 일치 · URL 포함/일치. 모든 검증은 최대 8초 동안 조건이 맞을 때까지 기다린 뒤 판정합니다
- 각 단계의 `✎`(편집)로 입력값·URL·키·대기시간·설명을 고치고 `↑ ↓`로 순서를 바꿀 수 있음
- **▶ 전체 재생**: 저장된 단계를 현재 탭에서 신뢰 이벤트로 재생. 실행 중인 단계가 파란색으로 표시되고, 단계별 소요 시간이 함께 기록됨
  - 실패한 단계에는 **실패 시점 스크린샷**이 붙고, **실패 시 계속** 체크박스를 켜면 첫 실패에서 멈추지 않고 끝까지 실행해 모든 실패를 한 번에 확인
  - 단계 목록 아래 **실행 기록**에서 최근 10회 결과를 다시 볼 수 있음 (이 브라우저에만 저장, 팀 공유되지 않음)
- 각 단계의 `🔎`(화면에서 강조) / `▶`(단건 실행) / `✎`(편집·순서) / `✕`(삭제)
- **내보내기 / 불러오기**: 시나리오를 JSON으로 저장·복원 (자동으로도 `storage.local`에 저장됨)

> 재생 시 크롬 상단에 _"Po-Cake이 이 브라우저를 디버깅하고 있습니다"_ 배너가 뜹니다.
> 이는 `chrome.debugger`(CDP)로 **진짜 유저와 구분되지 않는 신뢰 이벤트**를 쏘기 때문이며, 정확도를 위한 의도된 동작입니다.

## 여러 시나리오 관리

- 상단 **시나리오 선택 바**에서 드롭다운으로 시나리오 전환
- 드롭다운은 **팀 시나리오**(게시됨, 실행자에겐 읽기 전용)와 **내 초안**(이 브라우저) 두 그룹
- `＋`(새 초안), `✎`(이름변경), `⧉`(초안으로 복제), `↑`(게시자: 초안을 팀으로 승격), `🗑`(삭제)
- 초안은 자동으로 `chrome.storage.local`에 저장 (오프라인 유지)
- 기존 단일 시나리오 데이터는 처음 실행 시 "기본 시나리오"로 자동 이전됨

## 팀 공유 (Supabase) - 게시자 / 실행자 모델

시나리오는 두 종류입니다.

|                 | 누가                               | 어디에                        | 편집     |
| --------------- | ---------------------------------- | ----------------------------- | -------- |
| **팀 시나리오** | 게시자가 게시한 확정본 (v1, v2, …) | Supabase → 모든 설치에 미러링 | 게시자만 |
| **내 초안**     | 각자 자기 브라우저에서 만든 것     | `chrome.storage.local`        | 누구나   |

- **실행자**(팀원 대부분)는 설치만 하면 됩니다. 패널을 열면 최신 팀 시나리오를 자동으로 받아 ▶로 실행하고, 원하면 초안을 만들어 볼 수 있습니다. 로그인 없음.
- **게시자**는 ⚙에서 로그인한 뒤 팀 시나리오를 편집하고 **[↑ 게시]** 로 새 버전을 내놓습니다. 초안은 `↑`로 팀 시나리오로 승격할 수 있습니다.
- 팀원이 만든 좋은 초안은 **내보내기**(JSON)로 게시자에게 보내고, 게시자가 **불러오기** → 승격 → 게시합니다.

쓰기 권한은 UI가 아니라 Supabase의 RLS 정책이 강제합니다 - 배포본을 뜯어 버튼을 되살려도 서버가 거부합니다.

**1) Supabase 프로젝트 준비 (게시자가 최초 1회)**

1. [https://supabase.com](https://supabase.com) 에서 버전 생성 (무료 티어로 충분)
2. **SQL Editor**에서 사이드 패널 ⚙ 모달 하단의 설정 SQL 실행 → `suites`, `scenarios`, `publishers`, `releases` 테이블과 정책 생성 (다시 실행해도 안전)
3. `publishers` 테이블에 게시자 이메일 추가:
   ```sql
   insert into publishers (email) values ('you@company.com');
   ```
4. **Authentication → Providers → Email**: **Enable sign ups 끄기** (아무도 스스로 가입 못 하게)
5. **Authentication → Users → Add user**: 게시자 이메일 + 비밀번호로 계정 생성 ("Auto Confirm User" 켜기)
6. **Project Settings → API**에서 `Project URL`과 `anon public` 키 복사

**2) 빌드에 연결 정보 심기**

```bash
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
#   VITE_SUPABASE_URL=https://xxxx.supabase.co
#   VITE_SUPABASE_ANON_KEY=eyJhbGci...
npm run build
```

→ 이 `dist/`를 배포하면 실행자는 설치 즉시 팀 시나리오를 받습니다. 사용자별 연결 설정 화면은 없습니다.
`.env` 없이 빌드하면 팀 섹션이 숨겨지고 초안만 있는 완전 오프라인 빌드가 됩니다.

> anon 키는 공개용 키라 배포본에 포함돼도 됩니다. 이 키로 할 수 있는 일은 RLS가 정하며,
> 설정 SQL은 **읽기: 누구나 / 쓰기: 로그인한 게시자만**으로 만듭니다.
> 따라서 배포본을 가진 사람은 팀 시나리오를 **읽을 수** 있습니다 - 비밀번호 같은 값은 시나리오에 넣지 마세요.

**3) 게시**

- ⚙ → 게시자 이메일/비밀번호로 로그인 (세션은 브라우저에 유지됨)
- 팀 시나리오를 고치거나 초안을 `↑`로 승격하면 "게시 안 된 변경 N개"가 표시됨
- **[↑ 게시]** → 이 버전의 변경분이 새 버전(v+1)으로 올라가고, 실행자는 다음에 패널을 열 때 받음. 시나리오 상태줄의 **이것만 게시**로 하나만 올릴 수도 있음
- 게시자가 여럿이어도 안전합니다: 게시(와 `↻`)는 먼저 서버 최신본을 받아 **내가 바꾼 시나리오만 그 위에 겹쳐 얹은 뒤** 올립니다. 같은 시나리오를 둘 다 고쳤을 때만 "내 것 / 서버 것"을 물어봅니다. **되돌리기**는 내 변경을 모두 버리고 서버 상태로 돌아갑니다.

**4) 버전(suite) - 제품 버전별 시나리오 세트**

- 팀 시나리오는 버전 단위로 관리됩니다 (예: `v2.3`, `v2.4`). 실행자는 상단에서 버전을 고르고 그 안의 시나리오를 봅니다
- 게시자: `＋`(새 버전) `✎`(이름) `⧉`(시나리오를 복사해 새 버전 - 새 제품 버전 시작할 때) `📦`(보관: 목록 아래로 내려가지만 실행은 가능)
- 게시 버전은 버전마다 따로 셉니다 ("v2.4 버전 v3")
- **▶ 버전 전체 실행 / ▶ 폴더**: 버전(또는 한 폴더)의 시나리오를 순서대로 모두 실행(회귀 테스트). 시나리오별 ✅/❌ 요약이 뜨고, 행을 누르면 그 시나리오의 실패 단계·스크린샷을 볼 수 있음. 한 시나리오가 실패해도 다음 시나리오는 계속 실행

**5) 게시자 추가·제거**

- 추가: Users에서 계정 생성 + `publishers`에 이메일 한 줄
- 제거: `publishers`에서 삭제 (계정은 남아도 쓰기 불가)

## 배포 - 크롬 웹스토어 미등록(Unlisted)

검색에는 안 뜨고 **링크 아는 사람만** 설치하는 방식. 자동 업데이트됨.

1. **설정 심어 빌드**: 위 (A)대로 `.env` 채우고 `npm run build`
2. **dist 압축** (PowerShell):

```powershell
 Compress-Archive -Path dist\* -DestinationPath po-cake.zip -Force
```

3. **개발자 등록**: [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole)에서
   개발자 계정 등록(최초 1회 $5) → **새 항목** → `po-cake.zip` 업로드
4. 스토어 등록정보(아이콘·설명·스크린샷) 작성
5. **공개 범위(Visibility)** → **미등록(Unlisted)** 선택 → 제출 → 검토 후 게시
6. 게시되면 나오는 **설치 링크를 팀에 공유** → 동료는 링크 → "Chrome에 추가"로 설치

> 링크만 있으면 누구나 설치 가능합니다(검색에는 안 뜸). 계정 제한이 필요하면
> 공개 범위를 **비공개(Private)** 로 두고 테스터 이메일을 등록하세요.

```
manifest.config.ts, vite.config.ts, index.html
```
